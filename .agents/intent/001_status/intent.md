## 문제
세션을 시작할 때 "지금 어디까지 왔고 다음에 무엇을 하는가"를 알려면 사람과 에이전트 모두 여러 파일을 직접 열어야 한다.
`.agents/intent/`의 intent·spec·plan 상태, `.loctx/ticket/`의 열린 일, 버스에 남은 인계 파일, 마지막 history, 하네스 버전과 드리프트가 전부 따로 있다.
워크플로 블록은 세션 시작에 `reins status`를 부르라고 하지만 아직 없다. 그래서 이 레포는 AGENTS.md에 임시 규칙(`4_implementation.md` + 최신 history)을 두고 있다.

## 바라는 결과
- `reins status` 한 번으로 현재 상태와 다음 할 일을 본다. 사람이 읽는 출력과 `--json`.
- intent마다 "사람이 할 일"(승인 대기, spec 요약 확인 대기)을 루프가 실제로 멈추는 규칙(T1)과 같은 판단으로 보여준다 — status와 check가 서로 다른 말을 하지 않는다.
- ticket마다 다음에 돌릴 check를 알려준다.
- 이 레포 AGENTS.md의 임시 규칙을 걷어낸다.

## 영향 범위
`cli/` (새 명령 하나, 기존 검증 로직 재사용), 이 레포 `AGENTS.md` 프로젝트 절. 하네스 원본(`harness/`)과 스킬은 바꾸지 않는다.

## 제약
- 읽기 전용. 파일을 쓰지 않고 모델을 부르지 않는다(설계 §9). 검증기가 아니므로 종료 코드는 상태와 무관하게 0(레포 밖이면 2).
- 판단 규칙은 `check`와 한 곳에서 나온다. status만의 규칙을 새로 만들지 않는다.
- 단위마다 커밋, `pnpm check` 통과.
