## Project

**reins** (`@bluenyang/reins`, GitHub `bluenyang/reins`) — a reusable agent harness and loop (roles, loop policy, handoffs, knowledge,
gates) for BlueNyang's and Team Croffle's repositories, installable in new repositories and
migratable from the harnesses those repositories already use.

### Current phase

The project ran **survey → planning → design → implementation**, in that order. Survey, planning and
design are done (`docs/proposal.md`, `docs/design.md`); the current phase is **implementation, round
one** (design §11): the verifier first, then the harness sources, then self-install and self-migrate
of this repository.

- The design document is the reference. If an implementation needs to differ, change
  `docs/design.ko.md` (and the English edition) **in the same commit** before the code.
- Scripts are TypeScript. No Python in this repository (R65).
- Stop conditions, roles and file formats come from `docs/design.md`; do not invent parallel ones.

### Stack and commands

- Node ≥ 20, pnpm, TypeScript (ESM). Lint/format: oxlint, oxfmt. Tests: vitest. Hooks: husky.
- `pnpm check` — lint, format check, typecheck, tests. Run before reporting done.
- `pnpm build` — `cli/src` → `cli/dist` (the `reins` bin).
- `node cli/dist/reins.js check --stage pre-commit|pre-push` — the harness verifier the hooks call.
  Exit codes: 0 continue, 10 hold, 20 stop, 30 escalate.
- Never read `.env`, `.env.*.local`, `secrets/**`, `*.properties`, `*.key`, `*.pem`. `*.example*` is fine.

## Workflow

- Session start: `AGENTS.md` → `docs/ROADMAP.md` → open intents in `.agents/intent/` → `reins status`.
- Work comes from `.loctx/ticket/`; one file is one item; delete it when done after writing a line in `.loctx/history/`.
- **Committing is part of doing the work.** Land each finished unit — one coherent change that builds on its own — as its own local commit as you go, on the feature branch. Do not batch a whole ticket into one commit, and do not wait for permission to commit locally. Never commit on the default branch; never bypass hooks.
- Before a non-trivial decision: `reins recall <keyword>` (knowledge, history, symptoms).
- The verifier runs at every transition (`reins check`). Verdicts: CONTINUE · HOLD (ask the user) · STOP (recorded, resumable) · ESCALATE. A stop names its reason id (A1–G2).
- Anything that leaves the machine happens only in the deploy role inside the pre-release loop, or on the user's explicit instruction.
