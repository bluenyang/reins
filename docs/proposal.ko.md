## 2. 목표

**프로젝트 규모에 맞춰 harness → loop → graph 를 설치·마이그레이션·업데이트하는 툴**을 만든다.
에이전트는 **허가된 역할만, 지정한 동작만** 하고, 사람은 **게이트 결정**만 한다.

비목표 (이번 프로젝트가 아닌 것):
- 특정 프로젝트(croffle 등)의 기능 개발
- 벤더 CLI 자체의 대체·래핑
- 모델 선택의 자동 최적화 (바인딩은 사람이 정한다)

## 3. 요구사항

### 3-1. 구조 — 사다리
- **R1** 세 단(harness / loop / graph)이 있고, 윗단은 아랫단의 **상위집합**이다. 올라갈 때 층을 더하고 내려올 때 지운다.
- **R2** 그래프를 먼저 설계하고 루프·하네스는 **거기서 깎아 내린다.** 세 단이 같은 원본을 공유한다.
- **R3** 단순 스크립트 프로젝트는 그래프용 장치(버스·역할·바인딩) **없이** 동작한다.

### 3-2. 하네스 — 제어 (최우선)
- **R4** 에이전트는 **역할에 허가된 동작만** 한다. 역할마다 "못 하는 것"이 명시된다.
- **R5** **하네스 검증기**가 있다: 루프가 **언제 어떻게 빠져나가는지** 검증하는 제어기. 산출물 검사기가 아니다.
- **R6** 정지 조건에 비가역 작업·`[ask user]`·반복 실패 외에 **비용 임계**와 **사용자 중단 신호**가 포함된다.
- **R7** 결정론이 필요한 곳(게이트·설치·검사)은 에이전트가 아니라 **스크립트**가 한다. 멱등이어야 한다.
- **R8** 하네스는 단독·루프·그래프 어디에도 얹힌다. 달라져야 하면 **조각을 조합**해서 만든다.
- **R9** 에이전트가 **자기 권한 파일을 고치는 경로**가 막힌다 (드리프트 검사).

### 3-3. 루프
- **R10** 버전·목표 시점을 주면 plan → work → test → release 를 **자가반복**한다 (현재 pipit-hub·sdsrms 수준 유지).
- **R11** 검증·판정이 구현과 **분리된 주체**에서 돈다.
- **R12** 서브 에이전트를 적극 쓴다.

### 3-4. 그래프
- **R13** 역할: PM · 기획/설계 · 구현(PL + 구현자) · 지식 탐색 · 검증 도구 · 코드 리뷰 · QA 설계 · QA 수행 · 배포 · 문서.
- **R14** **역할 분리 ≠ 모델 분리.** 모든 역할을 한 모델로 돌려도 성립한다. 벤더·모델은 바인딩으로 바꾼다.
- **R15** 에이전트간 통신은 **스키마가 강제된 인계 파일**로 한다. 자율 Markdown이 아니다. 끝나면 지운다.
- **R16** 지식 탐색 역할은 파일을 쓰지 않는다 — 주도 모델에게 정보만 준다.
- **R17** QA는 임계점 근처라도 애매하면 **실패**로 판정한다.
- **R18** QA 2회 실패 → 상위 모델 개입 → 그래도 실패 → 자문 역할 → 권한 초과면 사용자 허가.
- **R19** 기획/설계는 사용자가 **과정을 이해하고 관제**할 수 있게 질의서·분석 리포트를 낸다.

### 3-5. 툴
- **R20** `[install | migrate | update] [harness | loop | graph]`.
- **R21** 설치는 **2단**: ① CLI가 결정론적으로 파일 배치·바인딩 질문·게이트 선언 ② PM 에이전트가 프로젝트를 읽고 컨텍스트를 채운다.
- **R22** 바인딩은 **구독에 맞춰** 질문한다. Claude 하나만 있어도 설치된다.
- **R23** 게이트 명령은 하드코딩하지 않는다. 프로젝트가 **선언**하고 루프는 선언만 본다.
- **R24** `migrate`는 출발 세대(2·3·4세대)를 **판별**하고 무엇을 옮길지 안다.
- **R25** `update`는 프로젝트 조정을 **부수지 않는다**: 파일 소유권(업스트림/프로젝트/섞임), 관리 블록, 오버라이드 선언, 버전 핀.
- **R26** 섞이는 파일은 **`AGENTS.md` 하나**를 목표로 한다.
- **R27** promote(프로젝트 → 업스트림)는 사람이 결정한다. 툴은 오버라이드 목록을 보여 준다.
- **R28** 드리프트 검사가 훅과 CI 양쪽에서 돈다: 형식(표준 검증기) · 일치(재생성 diff) · 규약.
- **R29** **첫 migrate 대상은 이 레포 자신.**
- **R30** TS로 쓰고 `npx`로 실행한다. 대상 프로젝트의 스택에 의존하지 않는다.

### 3-6. 형식 — 표준
- **R31** 지시는 `AGENTS.md`, 절차는 `SKILL.md`(Agent Skills) 표준을 따른다. 새 형식을 만들지 않는다.
- **R32** 표준이 없는 것(역할·권한·훅)만 우리 원본에서 벤더별로 **생성**한다. 생성물은 커밋되고 손으로 고치지 않는다.
- **R33** 단(tier)은 `metadata`에, 권한은 `allowed-tools`와 벤더 설정 **둘 다**에 쓴다.

### 3-7. 디렉터리
- **R34** 커밋 경계가 **이름에서 보인다**: 우리가 정한 이름은 점 없음 = 커밋, 점 = gitignore. 벤더가 정한 이름은 커밋 생성물.
- **R35** `.loctx/`(구 `.ai/`)가 유일한 gitignore 공간 — ticket · reports · pr · release · context · bus · 로컬 test · history(버전별 완료 보고서) · ROADMAP.local. 커밋되는 에이전트 컨텍스트는 전부 `.agents/`(intent · knowledge · harness · skills · SKILLS.md).
- **R36** 검증 자산은 **커밋**된다. 승격 기준과 실값 혼입 방지 규칙이 있다.
- **R37** 장기 지식은 하네스와 **분리**된 커밋 공간에 쌓인다 (하네스는 교체되고 지식은 쌓인다).

### 3-8. 문서
- **R38** AI용 문서(`AGENTS.md`·컨텍스트·메모리)는 영어. 사용자 공용(계획·작업·리포트·핸드오프)은 한글, 단계 책임 에이전트가 쓴다.
- **R39** 사용자 공용 문서는 **리딩이 병목이 되지 않게** 핵심만 (3초 테스트, 다이어그램).
- **R40** 공개 문서·PR·릴리스 노트·블로그는 지정 역할이 쓰고 `im-not-ai`로 윤문한다.
- **R41** `AGENTS.md` 같은 중요 문서는 총괄 역할만 수정한다.

- **R67** 공개 문서는 **영어가 기본**(`README.md`, `docs/*.md`)이고 한글판은 **`.ko.md` 쌍**으로 둔다. 서로 링크한다. 사용자가 한글로 쓴 문서는 한글판이 원본이고 영어판이 번역이다 (사용자 2026-10-25).

### 3-9. 지식
- **R42** 결정·교훈이 gitignore 밖으로 나가는 **커밋되는 통로**가 있다. 비밀값·호스트·개인정보는 걸러진다.
- **R43** 지난 결정을 **증상으로도** 찾을 수 있다 (명사 색인만이 아니라).
- **R44** 반복 실수가 규칙으로 **승격**되는 경로가 있다 (사람 확인 후).

### 3-10. 추적성 · 증거 (2026-10-24 추가, 플레이북 조사에서)
- **R45** 구현이 계획에서 벗어나면 **같은 커밋에서 계획을 갱신**한다. "머지된 diff ↔ 커밋된 계획 일치율"을 지표로 둔다. 훅으로 강제할 수 있어야 한다.
- **R46** 검증 증거는 규칙이 아니라 **형식**으로 보장한다: 툴체인(테스트·빌드·스크린샷)의 출력을 **그대로 붙인다.** 요약이나 "통과"라는 말만으로는 통과가 아니다.

### 3-11. 질의서 답에서 추가 (2026-10-25, `2_questions.md`)
- **R47** **요구를 "통과하기 위한" 구현을 금지한다.** 하드코딩, 일부 화면에서만 정상처럼 **보이게** 하는 구현은 역할 불문 금지. 요구를 파악해 근본적으로 적용되는 설계·구현만 허용 (Q1 공통 금지선).
- **R48** 사용자 중단은 **채팅 · Ctrl+C · 세션 종료** 세 경로 모두를 지원한다. 중단 시 하던 작업을 멈추고 **재개에 필요한 정보를 기록**한다 (Q3-a·b).
- **R49** 비용 임계는 **토큰** 단위이며 **PM 역할이 프로젝트 상황에 맞춰 지정**한다 (Q3-d).
- **R50** 정지 조건은 **명확히 열거**된다 — 지금처럼 산문에 흩어지지 않는다 (Q3-f).
- **R51** 검증 도구 역할은 실패를 **PL·구현자가 바로 파악할 수 있게 요약**한다. 요약으로 부족하면 PL이 추가 검증·분석할 수 있다 (Q1).
- **R52** 코드 리뷰 역할은 **수정 제안(방향성)까지** 한다. 직접 수정·머지 결정은 못 한다 (Q1).
- **R53** QA 설계 역할은 **코드를 보지 않고** 아키텍처·ROADMAP·intent로 설계한다. 코드를 보는 QA는 리뷰 역할의 일 (Q1).
- **R54** `.loctx/history/`는 **노하우(암묵지, 사람마다 다름, 로컬)**, `.agents/knowledge/`는 거기서 정리한 **명시지(결정·유의점, 커밋)**. 노하우의 자율성은 보장하고 명시지만 공유한다. knowledge 항목은 "어떻게 했다"가 아니라 "무엇을 왜 정했고 어디에 적용되나"로 쓴다 (사용자 2026-10-25).
- **R55** 질의서는 **큰 것부터 묻고 구체화**한다. md 파일과 채팅 **둘 다**로 답할 수 있고, 질문할 때 채팅으로도 보여 줄지 묻는다 (Q9-e).
- **R56** 같은 결정을 에이전트가 **다시 묻는 현상**을 막는다 — 결정 검색이 파일 수십 개 규모에서도 동작해야 한다. 벡터/의미 검색 도구는 있으면 쓰고 없으면 만들 수 있다 (Q7-a).

### 3-12. 바인딩의 자유도 (사용자 2026-10-25)
- **R57** 역할별 모델 기본값은 §3-5·C-5의 배치로 두되, **install 때 벤더 무관하게 어느 역할에든 어느 모델이든** 넣을 수 있다. Fable을 PM으로, GPT 없이, GPT만으로 — 전부 가능해야 한다. (R14 "역할 분리 ≠ 모델 분리"의 운용 요구)
- **R58** install 뒤에도 **명령 하나로** 바인딩을 바꿀 수 있다 (`configure bindings` 류).
- **R59** install과 바인딩 변경 모두 **manual(대화형 질문)과 auto(설치된 CLI·구독을 감지해 기본 배치 자동 적용) 두 모드**가 있다.

### 3-13. 언어 · 의존성 (사용자 2026-10-25)
- **R60** 툴과 하네스는 **언어 범용**이다. AI용 문서는 영어, 사용자용 문서 언어는 설정값. 한국어 전용 가정을 코드·템플릿에 넣지 않는다.
- **R61** 윤문(R40) 등 외부 스킬이 필요한 단계는 **언어별 슬롯**이다. 한국어는 `humanize-korean`, 다른 언어는 해당 도구 또는 생략.
- **R62** 다른 스킬·플러그인에 **의존하지 않는다.** 전부 선택 — 설치 시 감지해 **권장**하고 없으면 기능이 빠질 뿐 깨지지 않는다. 플러그인 매니페스트의 `dependencies`(필수 의존)는 비운다.
- **R63** `ROADMAP`은 둘이다: `.loctx/ROADMAP.local.md`(산발적 아이디어, 미확정) → 타당성 검토 후 **`docs/ROADMAP.md`**(확정, 공개).
- **R64** 승인 사슬: intent = **사용자 승인** / spec = **PM + QA 1차 검토** → **사용자에게 "이렇게 이해했습니다" 요약 3~5줄, 거부권** / plan = **QA 단순 검토**. 꼼꼼한 검토는 에이전트, 최종은 사람 — 사람은 요약만 보고 스톱할 수 있다 (개입 축 ③의 공식화). 루프 단에선 요약 생략 (사용자 2026-10-25 확정).

### 3-14. 이 레포 자신 (사용자 2026-10-25 확정 시)
- **R65** 레포의 스크립트는 **Python을 쓰지 않는다.** CLI·생성기·검사는 TS/Node, 셸은 한 줄짜리 훅 호출 정도까지. (사용자 선호. 외부 도구가 Python이면 호출만 한다.)
- **R66** 이 레포는 **자기 루프로 자기를 개선**한다. 자기 자신이 첫 설치·마이그레이션 대상(S1)이고 이후 모든 변경은 자기가 만든 intent → spec → plan → ticket 사슬을 탄다. 툴이 못 하는 일이 생기면 그것이 다음 intent다.

## 4. 범위

| 차수 | 내용 |
|---|---|
| **1차** | **graph 설계**(역할·인계·정지 조건·바인딩) + 디렉터리·형식 확정 + `install graph` + 이 레포 self-migrate |
| 2차 | 그래프에서 깎아 낸 loop · harness, `migrate`(세대 판별), `update` |
