# roadmap

## 1. When
The user brings an idea, a change of plan, or asks what comes next.

## 2. Procedure
1. Write ideas as they come into `.loctx/ROADMAP.local.md` under the version they may belong to, marked as ideas — also while another version is being worked on. An idea is never lost and never starts work by itself.
2. Talk them through with the user until they are settled: what, why, which version, what is out. Ask what only the user can decide. A version name alone is not a settlement, and naming a version says where an item belongs — it is not an instruction to start it.
3. Only what the user settled goes into `docs/ROADMAP.md` (and its other language edition, if the project keeps one). Never put an unsettled idea there. A settled item may be entered while another version is still in work.
4. Name the version of the next work. Hand over to `intent` when the user starts that work and the previous loop is closed (its retro is done).

## 3. Delegation
Check `.loctx/delegation.local.md` if it exists, otherwise the delegation table in AGENTS.md. If the role group named here has a model, hand it the work with the list of files and decisions it needs and wait for its report; otherwise do it yourself. Read-heavy work (research, large log summaries, review) or urgent parallel work on independent units may go to subagents of your own model. A role never calls another model; it returns to you.

## 4. Files and lifetime
- `.loctx/ROADMAP.local.md` — local, the user keeps it.
- `docs/ROADMAP.md` — committed, kept.

## 5. Next
`intent` — when the user starts the work.

## 6. Stop and ask
- The idea changes a past decision or the product boundary.
- You are about to write something to `docs/ROADMAP.md` the user did not settle.
